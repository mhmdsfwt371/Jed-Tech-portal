# ADR-0025 — نقاط كل مهندس من الأوزان المعتمدة ونشر مراجعات المدير

| | |
|---|---|
| **الحالة** | معتمد |
| **التاريخ** | 2026-10-30 |
| **النسخة** | v8.13 |

## السبب

«مؤشراتي» كانت تعرض الإجمالي، لكن المهندس يحتاج معرفة كيف حُسبت نقاطه: نوع المهمة، عددها، وزنها، وإجمالي النقاط. كما أن تعديلات صفحة «الأوزان» تُحفظ على جهاز المدير ولم يكن لها اعتماد واضح يجعلها تصل لبقية الفريق.

## القرار

1. تحفظ كل بطاقة `monthCard()` جديدة كشف `breakdown` مجمّعًا من المهام المنجزة فقط؛ الوزن الفعلي من ملف الأوزان. تظهر الأنواع غير المعروفة باستخدام الوزن الافتراضي، وتبقى بطاقة الشهر المقفول القديمة كما هي دون عرض تفاصيل افتراضية تخالف رصيدها المحفوظ.
2. رابط الفريق `?portal=team` يستخدم فقط ملف `weights.json` الرسمي المنشور. تعديل صفحة الإدارة يبقى على جهاز المدير كمسودة ومعاينة حتى يعتمد ويُنشر.
3. في الإدارة زر **«اعتماد وتجهيز النشر»** يوضح الفروق، ويجهّز النص الكامل لـ `weights.json` مع الحفاظ على البنية وبيانات `tiers`. يمكن نسخ الملف وفتح محرره في GitHub، ثم إتمام Commit بحساب مخوّل. **الزر لا ينشر وحده** ولا يطلب أسرار GitHub؛ لا يوجد Backend أو اعتماد GitHub من داخل الموقع.
4. عامل الخدمة يتعامل مع `weights.json` بطريقة Network-first مع نسخة احتياطية عند عدم الاتصال، حتى يظهر التغيير المنشور عند الزيارة أو تحديث البيانات من ماي أفاقي، دون إصدار تطبيق جديد. تحديث ملفات التطبيق نفسه يظل عبر النسخ المعتادة.

## حدود الحساب والخصوصية

- نقاط «مؤشراتي» الشخصية من المهام المنجزة التي يسمح بها MyAFAQY؛ الأنشطة الإضافية غير المتاحة في هذا السحب لا تُحسب في البطاقة الشخصية. لا تُخترع بيانات.
- الأوزان المقفولة القديمة محفوظة ولا تُحسب بأوزان جديدة بعد إغلاق الشهر.
- لا تُغيّر المسودة نتائج المهندس في رابط الفريق، حتى لو استُعمل نفس المتصفح الذي تعمل عليه الإدارة.
- لا حماية حقيقية للواجهات بالروابط وحدها؛ التعديل المنشور يتطلب صلاحيات GitHub الفعلية.
